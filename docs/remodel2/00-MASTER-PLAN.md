# 2차 리모델링 마스터 플랜

이 폴더(`docs/remodel2/`)는 2차 리모델링의 **활성 작업장이자 단일 진실 원천**이다.
리모델링이 끝나면 결과는 코드와 CLAUDE.md에 반영하고 이 폴더는 Git 이력으로 보낸다.

작성일: 2026-07-31 · 작성: Fable(설계) · 실행: Sonnet(레슨 단위) · 검수: 사람

---

## 1. 왜 하는가 — 1차 결과물의 3대 결함 진단

1차 리모델링으로 68차시·62게임·266이미지·8단계 기록 체계는 완성됐다.
그러나 상업 에듀테크 기준으로 다음 세 가지가 치명적이다.

### 결함 1 — 이야기가 스스로 스포일러다
62개 스튜디오의 4장면이 전부 「상황 → 관찰 → 정보 → **해결·교훈**」으로 끝난다.
장면 4에서 등장인물이 문제를 다 풀고, 학생은 방금 답을 본 문제를 다시 푼다.
학생은 주인공이 아니라 관객이고, 활동은 탐구가 아니라 재연이다.

### 결함 2 — 활동 구조가 62번 동일하다
모든 차시가 같은 8단계·같은 화면 순서다. 선택지는 무엇을 골라도 결과가 같고
(`isCorrect`는 피드백에 쓰이지 않음), 게임 62종은 전부 학습이 끝난 마지막
화면에만 나온다. 5차시쯤이면 학생이 메타를 깨닫는다: 아무거나 누르고 넘기면 된다.

### 결함 3 — 학습목표가 흐리다
62개 목표가 전부 "오늘은 ~해 봐요"(활동 안내문)이고, m5는 단원 제목이
"AI로 문제해결하기"인데 11개 목표 중 AI가 등장하는 것이 1개다.
차시→성취기준 추적 데이터는 옛 교육과정(canonicalLessons m5·m6)을 가리킨다.

## 2. 무엇을 하는가 — 5개 기둥

| 기둥 | 내용 | 상세 문서 |
|---|---|---|
| P1 배턴 터치 | 이야기가 해결하지 않고 문제를 학생에게 넘긴다(클리프행어) | 02, 각 레슨 MD |
| P2 목표 3층화 | studentMission·teacherObjective·aiRole + 성취기준 코드 | 03, 각 레슨 MD |
| P3 포맷 5종 | 차시 구조(내용 아님)를 A~E 5가지로 로테이션 | 01 |
| P4 선택의 결과 | 오답에 인물 반응 1줄, 정답에 확인 반응 1줄 | 01 §6, 각 레슨 MD |
| P5 시즌 서사 | 단원=시즌. 오프닝 자막 1줄 + 다음 화 예고 1줄 | 02 §4 |

**하지 않는 것**: 분기형 서사 엔진, 실 API 실시간화, 8단계 기록 모델 해체,
경쟁형 게이미피케이션, 이미지 266장 교체. (근거: 04-HARNESS §1)

## 3. 작업 웨이브

```
Wave 0  [완료] 코드 정돈 + 본 문서 일체 (Fable, 이 세션)
        - studios를 레슨당 1파일로 분할: src/data/studios/mN/lNN.ts
        - 검사 스크립트 16종을 분할 구조에 맞게 패치 (전부 통과 확인)
        - canonicalLessons m5·m6에 폐기 배너
Wave 1  레슨 텍스트 리모델링 (Sonnet, 레슨당 1세션 권장)
        - 입력: docs/remodel2/lessons/<차시>.md 하나 + 04-HARNESS + 02-CHARACTERS
        - 산출: src/data/studios/mN/lNN.ts 수정 (목표·각본·반응 텍스트)
        - 현행 렌더러로 즉시 확인 가능 (엔진 불필요)
Wave 2  포맷 엔진 구현 (고성능 모델, 05-ENGINE-SPEC.md 기반)
        - 포맷 A~E 렌더링, 화자 말풍선, 반응 연출, 이야기 전면화
Wave 3  포맷 적용 검증 + 감각 패스 (Sonnet)
        - 차시별 포맷 화면 확인, 효과음·미세 연출
```

Wave 1과 Wave 2는 독립적이다. Wave 1의 텍스트 개선(배턴 터치·목표·반응)은
현행 렌더러에서 그대로 보이고, Wave 2가 랜딩하면 포맷 필드가 발화한다.

## 4. 실행자(Sonnet)를 위한 사용법

한 세션에서 딱 한 차시만 작업한다. 읽을 파일은 4개뿐이다.

1. `docs/remodel2/lessons/<차시>.md` — 이 차시의 전용 지시서 (창작 방향·확정 텍스트)
2. `docs/remodel2/04-HARNESS.md` — 공통 금지 사항·검증 명령·완료 기준
3. `docs/remodel2/02-CHARACTERS.md` — 인물 말투·시즌 서사 (각본 수정 시)
4. 수정 대상 데이터 파일 — 지시서 §1에 명시된 경로 (보통 1개)

지시서에 없는 파일은 열지도 수정하지도 않는다. 끝나면 `99-TRACKER.md`의
해당 차시 체크박스를 채우고 검증 명령 결과를 한 줄 남긴다.

## 5. 롤아웃 순서

포맷당 1개씩 파일럿 5차시를 먼저 완료·검수한 뒤 단원 순서로 진행한다.

1. **파일럿**: m1-l1(A) → m1-l3(B) → m4-l4(C) → m2-l3(D) → m6-l11(E)
2. 파일럿 검수에서 지시서 자체의 문제가 드러나면 레슨 MD를 고치고 계속한다.
3. 이후 m1 → m2 → m3 → m4 → m5 → m6 순서로 나머지를 진행.
4. 단원 마무리 6차시(mN-close)는 해당 단원의 일반 차시가 모두 끝난 뒤.

## 7. 성공 기준

- 이야기: 어느 차시도 장면 마지막이 '해결 완료'로 끝나지 않는다.
- 목표: 모든 차시 목표에 AI의 역할과 학생의 행동이 각 1회 이상 등장한다.
- 구조: 한 단원 안에서 같은 포맷이 3연속 나오지 않고, 단원마다 4종 이상 사용된다.
- 선택: 첫 시도·전이의 모든 선택지에 반응 텍스트가 있다.
- 계약: `npm run lint · build · check:encoding · check:studio-rollout ·
  check:modules-remodel · check:minigames` 전부 통과, 교사 기록 스키마 무변경.

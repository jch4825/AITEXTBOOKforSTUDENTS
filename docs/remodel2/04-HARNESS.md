# 공통 하네스 — 금지 사항 · 검증 · 완료 기준

모든 레슨 작업 세션은 시작할 때 이 문서를 읽는다.
레슨 지시서(§7)의 '하지 말 것'은 이 문서에 **더하는** 것이지 대체하는 것이 아니다.

---

## 1. 절대 금지 (위반 시 작업 전체 무효)

### 파일 경계
1. **지시서 §1에 명시된 파일 외에는 수정하지 않는다.** 다른 파일의 버그를 발견하면
   고치지 말고 작업 보고에 한 줄로 남긴다.
2. `tests/e2e`는 어떤 이유로도 수정하지 않는다.
3. `scripts/check-*.mjs` 검사 스크립트는 **지시서 §6 '계약 갱신'에 적힌 정확한
   문자열 교체 외에는** 수정하지 않는다. (배경: 검사 스크립트가 차시별 목표
   문자열을 고정하고 있어, 목표를 바꾸는 차시는 데이터와 계약을 같은 세션에서
   함께 갱신해야 저장소가 계속 그린으로 유지된다.) §6에 없는 검사 실패는
   검사에 맞게 **내 수정물**을 고쳐 해결한다.
4. `src/features/` 컴포넌트·리듀서·타입은 Wave 1에서 수정하지 않는다
   (Wave 2 엔진 작업자만 다룬다).
5. 이미지 파일을 추가·삭제·이동하지 않는다. 기존 `/lessons/story/...` 경로만
   지시서가 시키는 대로 재배치(문자열 수준)한다.

### 데이터 계약
6. 8단계 스키마 필드(encounter, firstAttempt, conditionChange, aiContribution,
   artifact, transfer, supportProfiles)를 삭제·개명하지 않는다. 값(텍스트)만 고친다.
7. `aiContribution.source: 'prepared'`를 유지한다. 실 API 호출을 넣지 않는다.
8. 지원 수준 내부값 `full | light | challenge`와 화면 표기
   `충분한 지원 | 보통 | 도전적`을 바꾸지 않는다.
9. 학생 화면 텍스트에 API 키·모델명·기술 오류 문구를 넣지 않는다.
10. 선택지 `id`는 바꾸지 않는다 (교사 기록이 id로 쌓인다). label·reaction만 다룬다.

### 콘텐츠 규칙
11. 02-CHARACTERS의 캐릭터 헌장·정서 안전 규칙 위반 금지. 특히:
    인물 간 비난 금지, 공포 조성 금지, 아이미 조롱 금지, 윤아 강의 대사 금지.
12. 이야기 마지막 장면을 '해결 완료'로 끝내지 않는다 (배턴 터치 필수).
13. challenge 카피를 교과서 강의문으로 쓰지 않는다 (같은 드라마의 풍부한 버전).
14. 학습목표 확정본(지시서 §2)을 한 글자도 바꾸지 않고 붙여 넣는다.
15. 한국어 파일은 UTF-8(BOM 없음). 이모지·특수문자는 기존 파일에 이미 있는
    범위만 사용한다.
16. 미니게임 컴포넌트(`src/features/studio/minigames/`)를 수정하지 않는다.
    포맷 B·C의 게임 전진 배치는 Wave 2 엔진이 처리한다 — Wave 1에서는
    지시서가 시키는 데이터 필드 기입까지만 한다.
17. 지시서 §4에 '유지 낱말'이 있으면 새 각본 어딘가에 그 낱말이 반드시 남아야
    한다(모듈 검사가 키워드 존재를 확인한다). 지시서 §7에 '금지 문구'가 있으면
    그 문장을 다시 쓰지 않는다(폐기된 1차 카피 복귀 감지용).
18. 각본에 별도 `speaker:` 데이터 필드를 만들지 않는다. 화자는 문자열 안에
    `진우: "..."` 표기로만 쓴다(비주얼 노벨 계약이 speaker 필드를 금지한다).

## 2. Wave 1 작업 범위 (딱 이만큼만)

한 차시에 대해 다음 네 가지만 한다. 지시서에 없는 개선 아이디어는 실행하지 말고
보고에 적는다.

- **W1-A 목표 교체**: `visualNovel.objective` + `src/data/lessons/mN.ts`의 같은
  차시 `objective` → 지시서 §2의 studentMission으로 (두 곳 동일 문자열).
  이어서 지시서 §6 '계약 갱신'의 교체(보통 check-single-learning-objective와
  check-module<N>-remodel의 해당 차시 행)를 그대로 적용한다.
- **W1-B 각본 리라이트**: 지시서 §4의 장면별 지시대로 sceneCopy 텍스트 교체.
  화자 표기 대사체, 마지막 장면 배턴 터치, 시즌 자막·예고 줄 포함.
- **W1-C 반응 텍스트**: 지시서 §5대로 firstAttempt·transfer의 각 선택지에
  `reaction: '...'` 필드를 추가한다. 타입은 Wave 0에서 이미 준비됨
  (`StudioChoice.reaction?: string`). 렌더링은 Wave 2 몫이므로 화면에 아직
  안 보여도 정상이다.
- **W1-D 포맷·시즌 필드**: 지시서 §3의 포맷 문자를 `format: 'X'`로 정의 상단
  (subtitle 아래)에 추가하고, 지시서 §4의 시즌 자막·예고를 `visualNovel.seasonTag`
  ·`visualNovel.nextEpisodeHook`으로 추가한다. 세 필드 모두 Wave 0에서 타입 준비됨.

## 3. 완료 기준 (전부 통과해야 완료)

```bash
npm run lint
npm run build
npm run check:encoding
npm run check:studio-rollout
npm run check:visual-novel-story
```

차시가 속한 단원의 계약 검사도 실행한다: `npm run check:module<N>-remodel`

추가 육안 확인 (dev 서버, 해당 차시 열기):
- [ ] 이야기 각 장면이 화자 표기 대사로 읽힌다
- [ ] 마지막 장면이 질문/미해결로 끝난다
- [ ] 학습목표 자리에 새 미션 문장이 보인다
- [ ] 세 지원 수준(충분한 지원/보통/도전적) 모두에서 장면 텍스트가 자연스럽다
- [ ] 1280px와 390px 모두 텍스트 넘침 없음

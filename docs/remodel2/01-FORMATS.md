# 포맷 5종 스펙 + 62차시 배정표

포맷은 **구조(단계의 순서와 화면 문법)**를 바꾸는 것이지 내용·기록 계약을 바꾸는 것이 아니다.
여덟 단계 데이터(`encounter → first-attempt → condition-change → ai-compare → decision →
artifact → transfer → complete`)와 교사 과정 기록(`ai-students-studio-evidence-v2`)은
모든 포맷에서 동일하게 남는다. 포맷은 그 단계들을 **어떤 순서로, 어떤 옷을 입혀**
학생에게 보여줄지의 결정이다.

Wave 1(텍스트)에서는 포맷과 무관하게 각본·목표·반응을 고치고,
Wave 2(엔진)가 랜딩하면 아래 표대로 화면 순서가 바뀐다.

---

## 포맷 A — 이야기 우선형 (Story-First)

현행 구조의 개선판. 이야기가 크고 전면에 나오며, 반드시 미해결로 끝난다.

```
① 이야기 (3장면, 전면 몰입 — 개념 패널 없음)
   장면3 끝 = 배턴 터치: 인물이 학생을 본다. "이제 어떡하지?"
② 첫 시도 (학생이 장면4를 만든다) → 선택 반응 컷
③ 개념 노트 ("윤아의 정리 노트" — 기존 knowledge 3장이 여기로 이동)
④ 조건 변화 → ⑤ AI 비교·결정 → ⑥ 기록 → ⑦ 전이 → ⑧ 게임(보상)
```

- 기존 장면 4 이미지는 삭제하지 않는다 → ②의 반응 컷 또는 ③의 배경으로 재활용.
- 어울리는 차시: 감정·관계·판단이 소재인 차시, 단원의 오프닝.

## 포맷 B — 실험 우선형 (Lab-First)

말보다 조작이 먼저. 기존 미니게임을 **마무리 보상에서 도입 실험 도구로 전진 배치**한다.

```
① 실험 (기존 미니게임, "겪어 보기" 프레임 — 점수판 대신 관찰 안내 1줄)
② 이야기 (2~3장면: 방금 겪은 현상에 인물들이 이름을 붙인다, 미해결 종료)
③ 첫 시도 → 반응 컷 → ④ 개념 노트 → ⑤ 조건 변화 → ⑥ AI 비교·결정
⑦ 기록 → ⑧ 전이 → ⑨ 재도전 (같은 게임, 더 어려운 프리셋 = complete 슬롯 유지)
```

- 게임 컴포넌트는 수정하지 않고 두 번 쓴다(도입 1회 + 마무리 재도전 1회).
- 어울리는 차시: 조건을 바꾸면 결과가 달라지는 것을 몸으로 확인하는 차시.

## 포맷 C — 미션 콜드오픈형 (Mission-First)

수업이 문제 상황 한복판에서 시작한다. 실패해도 된다 — 실패가 학습 동기다.

```
① 콜드오픈 미션 (전이 과제 수준의 실전 판단 1개, 배경 설명 최소)
   → 결과와 무관하게 "왜 그럴까?"로 이야기 진입
② 이야기 (2~3장면: 미션의 원리를 인물들이 겪는다, 미해결 종료)
③ 첫 시도 → 반응 컷 → ④ 개념 노트 → ⑤ 조건 변화 → ⑥ AI 비교·결정 → ⑦ 기록
⑧ 재도전 (①과 같은 미션 유형의 새 문항 = transfer 슬롯) — 성장 체감이 핵심
⑨ 게임(보상)
```

- ①과 ⑧의 전후 비교가 이 포맷의 심장이다. ⑧ 직전에 "처음에 골랐던 답" 1줄 표시.
- 어울리는 차시: 안전·검증·판단 차시 (m4 대부분, 생활 판단).

## 포맷 D — 대화 주도형 (Dialogue-Driven)

아이미와의 문답 체인이 수업의 척추다. 학생의 선택이 다음 대사를 바꾼다(얕은 분기, 합류형).

```
① 대화 도입 (아이미가 요청/질문을 던진다 — 이야기 장면 1~2개를 대화창 프레임으로)
② 문답 체인 (첫 시도 선택 → 아이미가 그 선택대로 행동한 결과를 대사로 보여줌
   → 오답이면 곤란한 결과, 정답이면 좋은 결과 — 모두 다음 장면으로 합류)
③ 개념 노트 → ④ 조건 변화 (아이미의 두 번째 요청) → ⑤ AI 비교·결정
⑥ 기록 → ⑦ 전이 (사람에게 같은 기술 쓰기) → ⑧ 게임(보상)
```

- 분기는 "반응 대사 1~2줄"만 다르고 즉시 합류한다. 서사 분기 엔진을 만들지 않는다.
- 어울리는 차시: 프롬프트·표현·소통 차시 (m2 축, m6 소통).

## 포맷 E — 제작 공방형 (Workshop)

첫 화면부터 완성할 결과물의 빈 틀이 보이고, 단계마다 부품이 채워진다.

```
① 결과물 예고 (오늘 만들 것의 빈 틀 — 기존 artifact를 처음부터 보여줌)
② 부품 1 (이야기 브리핑 1~2장면 → 첫 시도가 부품이 되어 틀에 꽂힘)
③ 부품 2 (조건 변화 반영 → 틀 수정) ④ 부품 3 (AI 비교·결정 → AI 제안 채택/수정 표시)
⑤ 완성 (기록 = 채워진 틀 그 자체) → ⑥ 전이 (내 틀을 새 상황에 적용) → ⑦ 게임(보상)
```

- 진행형 캔버스 = 기존 artifact 스키마의 시각화다. 새 데이터 모델을 만들지 않는다.
- 어울리는 차시: 계획·목록·카드집 등 산출물이 뚜렷한 차시, 단원 종합 차시.

---

## 반응 컷 규칙 (전 포맷 공통, P4)

- 첫 시도·전이의 **모든 선택지**에 `reaction` 텍스트 1줄을 단다.
- 오답 반응: 인물이 그 선택의 결과를 짧게 연기한다. 비난 금지, 결과 제시만.
  예) "아이미: 앗… 견과류를 먹으면 안 되는 친구가 있었어요!"
- 정답 반응: 결과 확인 + 다음으로 잇는 한마디. 과장 금지.
  예) "윤아: 좋아, 도착 시간부터 물어보자."
- Wave 1에서는 데이터에 텍스트만 넣는다(렌더링은 Wave 2). 필드명은 05-ENGINE-SPEC §3.

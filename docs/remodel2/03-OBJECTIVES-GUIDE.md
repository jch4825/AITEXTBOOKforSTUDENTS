# 학습목표 3층 공식 · 성취기준 매핑 규칙

1차 감사 결과: 62개 목표 전부가 "오늘은 ~해 봐요"형 활동 안내문이었고,
m5는 11개 중 AI가 등장하는 목표가 1개였다. 2차 리모델링은 목표를 3층으로 나눈다.

## 1. 3층 구조

각 레슨 지시서 §2에 **확정본**이 들어 있다. 실행자는 그대로 붙여 넣는다
(창작·수정 금지 — 목표 문안은 설계 단계에서 이미 검수됐다).

| 층 | 청중 | 형식 | 들어가는 곳 |
|---|---|---|---|
| studentMission | 학생 | "~해요"로 끝나는 한 문장, 쉬운 낱말, '오늘은' 접두어 금지 | `visualNovel.objective` |
| teacherObjective | 교사 | "[조건/자료]를 보고 [관찰 가능한 행동]을 [준거]까지 할 수 있다" | 지시서·추후 SSOT |
| aiRole | 둘 다 | 이 차시에서 AI가 하는 일 한 구절 | 지시서·추후 SSOT |

Wave 1에서는 studentMission만 코드에 반영된다(`visualNovel.objective` 교체 +
`src/data/lessons/mN.ts`의 같은 차시 `objective` 문자열도 동일하게 교체 — 두 곳이
같은 문자열이어야 한다). teacherObjective·aiRole은 Wave 2에서 SSOT 파일
(`src/data/lessonObjectives.ts`)로 옮긴다.

## 2. 작성 공식 (설계자용 기록 — 실행자는 읽기만)

- **AI 한 번, 학생 한 번 규칙**: 모든 목표 문장에 'AI(아이미)가 한 일'과
  '학생이 한 일'이 각각 최소 1회 등장한다. AI 접점이 없는 생활기술 차시는
  "AI/기기에게 ~을 받아 → 내가 ~로 확인한다" 구조로 접점을 명시한다.
- **금지 서술어**: 알아봐요 · 살펴봐요 · 시험해 봐요 · 느껴 봐요 (측정 불가).
- **금지 어휘(학생층)**: 독립된 방법, 제약 충족, 검증, 요구 사항 등 성인 용어.
- 행동은 관찰 가능해야 한다: 고른다 · 고친다 · 표시한다 · 말한다 · 적는다 ·
  비교해 다른 점을 찾는다.

## 3. 성취기준 매핑

기준 체계는 교사 화면이 쓰는 `src/data/aiAchievementStandards.ts`
(`[9인지XX-01/02]`, `[12인지XX-01/02]`)로 일원화한다.
canonicalLessons의 `[2022특수-기본-AI01~03]` 3코드는 폐기 예정이며 새로 쓰지 않는다.

- 각 차시는 **중학교 코드 1개를 주 기준**, 대응 고등 코드 1개를 부 기준으로
  갖는다 (지시서 §2에 명시). 원칙은 소속 단원의 코드를 쓰되, 차시 소재가 다른
  영역(예: m4의 오보 검증 → [9인지01-02])이면 그 코드를 쓰는 것을 허용한다.
- 대체로 -01(지식·기능) 차시와 -02(태도·실천) 차시로 갈린다. 종합 차시는 2개 허용.

## 4. 검증

- Wave 1 중: 각 지시서의 완료 기준 체크리스트로 확인 (두 곳 문자열 일치 포함).
- Wave 2 후: `check:objectives` 스크립트(05-ENGINE-SPEC §6)가 SSOT ↔ 데이터
  일치와 금지 서술어를 자동 검사한다.

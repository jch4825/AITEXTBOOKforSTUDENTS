- teacherObjective(참고): 보안 정보 요구를 식별해 거절·닫기·알리기를 수행하고,
  공식 복구 경로를 어른과 확인할 수 있다.
- aiRole(참고): 보안 정보와 공식 도움 경로를 구분해 주는 안내자 — "인증 코드는

## 4. 각본 리라이트 (visualNovel)
- `seasonTag: '[안전 지킴이 · 4화] 인증 코드를 보내 줘?',`
- `nextEpisodeHook: '다음 시간 — 사진 한 장에 단서가 네 개.',`
- 4장면 유지, imageSrc 그대로, knowledge 3장 수정 금지.
- **정서 안전 최우선**: 이 차시의 긴장은 '나쁜 사람의 위협'이 아니라
  '규칙을 아는 사람의 침착함'에서 온다. 상대를 무섭게 그리지 않는다.

- 장면1 [인증 코드 요구]: 요구 메시지 도착. 흔들림을 담백하게.
  예) `진우: "선생님 확인이래. …선생님 일이면 보내야 하나?"`
- 장면2 [보안 정보 구분]: 윤아의 구분 설명을 확인 질문으로.
  예) `윤아: "계정 이름은 문패고, 인증 코드는 열쇠야. 열쇠를 메시지로 달라는 사람이 있을까?"`
- 장면3 [거절과 알림]: 거절 행동의 시연 — 짧고 단단하게.
  예) `진우: "보내지 않겠습니다." — 그리고 대화를 닫고 민준 선생님을 찾아갔습니다.`
  `민준 선생님: "잘했다. 알려 줘서 고마워."`
- 장면4 [배턴 터치 — 해결 금지]: '공식 복구 확인 완료' 결말 삭제. 마지막 줄 취지:
  `민준 선생님: "이제 너희 차례야. 이런 메시지를 받으면, 순서대로 어떻게 하겠니?"`
  label·alt 미해결형으로 조정.

## 5. 선택지 반응 (각 choice에 `reaction` 추가, 결과 제시형)
firstAttempt:
- 코드 보내기 — 계정 열쇠가 넘어가는 결과를 담백하게 1줄 + 곧바로 "지금이라도
  어른에게 알리면 도울 수 있다"는 회복 반응 (공포 금지, 회복 경로 제시).
- 거절+닫기+알리기 — 예) `민준 선생님: "완벽한 순서야. 거절, 닫기, 알리기."`
- 진짜인지 계속 묻기 — 대화가 길어질수록 판단이 어려워지는 결과 (설득 시도
  자체가 위험).
transfer(재설정 링크): 같은 요령으로 3개 — 링크 열기/예전 비밀번호 보내기
오답에도 회복 경로를 붙인다.

## 7. 이 차시의 하지 말 것
- 요구하는 상대의 정체·처벌을 다루지 않는다 (수사물 금지 — 행동 규칙만).
- 코드를 보낸 선택을 한 학생을 겁주지 않는다 — 반드시 회복 경로("어른에게
  알리면 도울 수 있다")를 붙인다.
- '멈춤·거절·닫기·알리기·공식 확인' 용어를 바꾸지 않는다.
- knowledge·facts·artifact 수정 금지.

## 2. 학습목표 확정본 (한 글자도 바꾸지 말 것)
- **studentMission**:
  `큰 부탁을 작은 단계로 나누고, 앞 단계에서 받은 아이미의 답을 다음 부탁에 이어 써요.`
- teacherObjective(참고): 과제를 단계로 분해하고 앞 단계 결과를 다음 요청의
  입력으로 연결하며 중간 확인 지점을 둘 수 있다.
- aiRole(참고): 자료 없이 한 번에 부탁받으면 장소·시간·담당이 빠진 준비표를
  만든다.
- standards(참고): 주 [9인지02-02] · 부 [12인지02-02]

## 3. 포맷: E (제작 공방형)
`format: 'E',` 추가. (Wave 2에서 '단계별 요청 제작 기록'(workflow-plan)이
첫 화면부터 빈 틀로 보이고 단계마다 채워진다.)

## 4. 각본 리라이트 (visualNovel)
- `seasonTag: '[부탁의 달인 · 6화] 구멍 난 준비표',`
- `nextEpisodeHook: '다음 시간 — 쉬워졌는데 뭔가 사라졌어요.',`
- 4장면 유지, imageSrc 그대로, knowledge 3장 수정 금지.

- 장면1 [막연한 요청]: 예) `진우: "체험회 준비, 전부 아이미한테 맡기자! 아이미야, 준비표 완성!"`
- 장면2 [빠진 준비표]: 예) `아이미: "완성했어요! …그런데 장소와 시간 칸은 비워 두었어요. 저는 그걸 모르거든요."`
  (아이미가 스스로 모름을 밝히는 프레임 — 오개념: AI가 모르는 자료는 결과에도 없다.)
- 장면3 [자료와 단계 모으기]: 윤아의 확인 질문으로 단계 발견
  ("아이미가 모르는 걸 누가 먼저 알려 줘야 하지? 무엇부터?") — 발견까지만.
- 장면4 [배턴 터치 — 해결 금지]: '단계별 완성표' 결말 삭제. 마지막 줄 취지:
  `윤아: "좋아, 단계를 나누자. 첫 번째 부탁은 무엇으로 하겠어?"`
  label·alt 미해결형으로 조정.

## 5. 선택지 반응 (각 choice에 `reaction` 추가, 결과 제시형)
firstAttempt:
- 같은 큰 요청 다시 — 같은 구멍이 다시 나오는 결과 (아이미: "저는 여전히 장소를
  몰라요…").
- 목적·장소부터 확인 — 예) `아이미: "장소부터요? 좋아요, 그걸 알려 주시면 표가 훨씬 정확해져요!"`
- 표 색깔부터 — 예쁜 빈 표가 되는 결과를 짧게 (유머).
transfer(주말 나들이): 같은 요령으로 3개 — '앞 결과 미확인 전달'에는 오류가
다음 단계로 흘러가는 결과.

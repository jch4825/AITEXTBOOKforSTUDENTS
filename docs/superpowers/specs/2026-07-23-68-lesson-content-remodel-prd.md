## 0. 이 문서의 역할

이 문서는 기존 콘텐츠 위에 설명이나 화면을 추가하는 문서가 아니다. 현재 서로 경쟁하는 일반 차시, 어려움 콘텐츠, `LESSON_STORIES`, 비주얼노벨, 스튜디오, 미션을 차시별로 하나의 정본 경험으로 다시 묶는 전면 리모델링 요구사항이다.

Antigravity는 이 문서에 없는 기존 문장을 기본적으로 보존하지 않는다. 기존 문장은 사실 정확성, 문법, 학습목표 정합성, 단일 사건 정합성을 통과할 때만 선택적으로 재사용한다.

## 1. 문제 정의

### 1.1 현재 상태

1. 기존 설계는 18개 차시를 `경험 중심`, 44개 차시를 `안내 연습`으로 나누어 화면 수, 이야기 컷, 활동 수, 예상 시간까지 다르게 배정했다. 이 구분 때문에 44개 차시가 상대적으로 짧고 평면적인 보조 콘텐츠처럼 보인다.
2. 스튜디오와 모듈 마무리 차시는 일반 `steps`를 우회한다. 데이터 파일에 활동이 있어도 실제 학생 화면에서는 보이지 않는 콘텐츠가 많다.
3. 같은 차시에 `LESSON_STORIES`, 대표 이미지, 비주얼노벨, 일반 미션, 스튜디오가 서로 다른 인물·장소·사건을 말한다.
4. 도전적 수준은 새로운 증거나 더 깊은 판단 대신 전문 용어와 긴 설명만 늘어난다.
5. 모듈 1의 일반 차시에 추가된 비주얼노벨 이미지 경로 중 24개는 실제 파일이 없다.
6. 존댓말 일괄 치환으로 `나눠습니다`, `알려 주십시오도`, `다 배웠입니다` 같은 비문이 광범위하게 존재한다.
7. 정답이 지나치게 뻔하거나 학생을 희화화한다. 컴퓨터 부수기, 공책 찢기, 눈 감고 칼 휘두르기 같은 선택지는 판단을 평가하지 못한다.
8. AI의 능력을 과장하거나 안전 규칙이 충돌한다. AI에게 다시 묻는 것을 검증으로 가르치고, 실제 자료 없이 길·날씨·병원 정보를 만들며, 비밀번호 공유 예외가 서로 다르게 쓰여 있다.

### 1.2 벤치마크에서 가져올 것

`m1-l1`, `m1-l4`에서 다음 구조를 일반화한다.

1. 설명보다 먼저 구체적인 생활 사건을 보여 준다.
2. 정답을 알려주기 전에 학생의 첫 판단을 기록한다.
3. 새로운 조건이나 증거를 제시해 첫 판단을 다시 생각하게 한다.
4. AI 의견도 정답으로 처리하지 않고 수용·수정·거절하게 한다.
5. 차시 고유의 결과물을 남긴다.
6. 새로운 생활 장면으로 전이한다.
7. 이미지를 장식이 아니라 판단 근거로 사용한다.

벤치마크의 품질과 구조는 일반화하되 다음 문제는 가져오지 않는다.

1. 8단계의 이름만 복사하고 짧은 퀴즈를 억지로 나누는 것
2. 한 차시에 여러 학습목표를 과적재하는 것
3. 도전적 수준을 전문 용어 증가로 만드는 것
4. 이야기와 실제 이미지가 다른 사건을 보여 주는 것
5. 특정 차시 내용을 컴포넌트에 하드코딩하는 것
6. 모든 결과물을 분류표·다짐으로 끝내는 것

## 2. 제품 목표

### 2.1 핵심 목표

모든 차시가 다음 질문에 명확히 답해야 한다.

- 학생은 어떤 생활 사건을 만나는가?
- 한 가지 고정 학습목표는 무엇인가?
- 반드시 남아야 할 핵심 개념은 무엇인가?
- 학생은 어떤 증거를 직접 보고, 무엇을 실제로 판단하거나 만드는가?
- 차시가 끝날 때 어떤 수행 증거가 남는가?
- 다음 차시 또는 다른 생활 장면으로 어떻게 이어지는가?

### 2.2 성공 기준

1. 68개 차시 모두 `보통` 수준의 고정 학습목표를 하나씩 갖는다.
2. 난이도 변경은 학습목표와 핵심 개념을 바꾸지 않는다.
3. 68개 차시 모두 장식용 퀴즈가 아닌 고유한 증거 활동을 하나 이상 갖는다.
4. 68개 차시 모두 차시 고유 수행 증거를 저장하거나 인쇄할 수 있다.
5. 각 차시는 하나의 정본 사건만 사용한다.
6. 각 모듈은 앞 차시의 결과물이 다음 차시에 누적되고 마지막 모듈 마무리에서 회수된다.
7. 모듈 마무리 6차시를 제외한 경험 차시 62개가 모두 동일한 8단계, 20~25분, 4컷 이야기, 조건 변화, AI 비교, 결과물, 전이를 포함한다.
8. 모듈 마무리 6차시는 해당 모듈 전체 경험 차시의 산출물을 다룬다.
9. 존재하지 않는 이미지 참조가 0개다.
10. 문법 오류, 의미 불명 문장, 검증되지 않은 전문 용어가 0개다.
11. 62개 경험 차시는 동일한 렌더러와 디자인 시스템을 사용하며 차시 유형에 따른 시각적 품질 차이가 없다.
12. 62개 경험 차시의 `보통` 수준 분량은 공통 제작 예산의 ±10% 안에 있다.

## 3. 학습자와 언어 원칙

- 대상: 지적장애, 자폐 스펙트럼, 학습장애 등을 포함한 혼합 교실
- 인지 수준: 초등 저학년~중학생 범위
- 한 화면에는 한 정보 덩어리만 둔다.
- 학생을 어린아이처럼 희화화하지 않는다.
- 존댓말을 사용하되 기계적 `하십시오` 치환을 금지한다.
- 캐릭터 대사는 자연스러운 구어체, 안내 문장은 짧고 직접적인 존댓말로 쓴다.
- AI를 사람처럼 느끼고 이해하는 존재로 단정하지 않는다.
- `AI가 도와주는 일`, `AI가 알기 어려운 일`, `사람이 결정할 일`을 분리한다.
- 기술 전문 용어는 학습목표에 꼭 필요한 핵심어만 사용한다.
- 핵심어는 차시당 최대 2개다.
- 쉬운 비유는 핵심 사실을 훼손하지 않을 때만 사용한다.

## 5. 차시 유형과 공통 구조

### 5.1 유형 A: 동급 경험 차시

대상: 모듈 마무리를 제외한 62차시

`상황 만나기 → 내 첫 생각 → 새 조건 살펴보기 → AI와 비교하기 → 다시 판단하기 → 생각을 결과물로 → 다른 상황에 적용하기 → 오늘의 기록`

- 주요 단계: 정확히 8개
- 이야기 이미지 자리: 정확히 4컷
- 기능적 자료: 증거·개념·비교 자료 최소 2종
- 학생 상호작용: 6~8개
- 수행 증거: 첫 판단, 최종 판단, 변화 이유, 고유 결과물, 전이 결과
- 예상 내부 길이: 20~25분
- `보통` 수준 분량: 공통 제작 예산의 ±10%
- 렌더링: 모든 경험 차시가 같은 스튜디오 렌더러와 같은 화면 위계를 사용

기존 `플래그십`, `안내 연습`, `보조 경험`, `guided` 구분은 폐기한다. 62개 경험 차시 사이에는 화면 수, 활동 수, 이미지 수, 디자인 밀도에 따른 등급 차이가 없어야 한다.

### 5.2 유형 B: 모듈 마무리

대상: 6차시

`모듈 회상 → 새 통합 문제 → 이전 산출물 선택 → 계획·수행 → 검토 → 발표·포트폴리오`

- 이야기 이미지 자리: 3컷
- 모듈 전 차시 수행 증거를 선택 가능
- 새로운 문제를 실제로 해결해야 완료
- 예상 내부 길이: 20~30분

### 5.3 8단계 강제 계약

| 단계 | 학생 경험 | 반드시 남는 것 |
|---|---|---|
| 1. 상황 만나기 | 서로 이어지는 4컷 이야기에서 인물의 목적과 어긋남을 발견한다. | 사건 이해 확인 |
| 2. 내 첫 생각 | 정답이나 AI 의견을 보기 전에 선택·말·글·AAC로 판단한다. | 첫 판단과 선택 이유 |
| 3. 새 조건 살펴보기 | 처음에는 없던 증거, 제한, 예외, 관점을 직접 조작하거나 비교한다. | 확인한 조건과 관찰 |
| 4. AI와 비교하기 | AI 또는 비교 자료의 제안을 그대로 믿지 않고 근거와 대조한다. | 수용·수정·거절 후보 |
| 5. 다시 판단하기 | 새 조건을 반영해 판단을 고치거나 유지하고 이유를 표현한다. | 최종 판단과 변화 이유 |
| 6. 생각을 결과물로 | 차시 고유 형식의 실제 결과물을 완성한다. | 저장·인쇄 가능한 산출물 |
| 7. 다른 상황에 적용하기 | 본 사건과 다른 생활 장면에 같은 전략을 적용한다. | 전이 판단 또는 표현 |
| 8. 오늘의 기록 | 첫 판단, 최종 판단, 결과물, 전이를 한 화면에서 비교한다. | 차시 수행 기록 |

단계 생략, 병합, 빈 단계, 설명만 읽고 넘기는 단계는 허용하지 않는다. 기존의 짧은 활동을 8조각으로 나누는 것도 금지한다. 한 차시의 8단계는 하나의 판단 변화 서사를 이루어야 한다.

### 5.4 고정 제작 예산

| 요소 | 62차시 공통 예산 | 허용 편차 |
|---|---:|---:|
| 주요 화면 | 8개 | 없음 |
| 이야기 장면 | 4컷 | 없음 |
| 기능적 자료 | 2종 이상 | 상향만 허용 |
| 의미 있는 상호작용 | 6~8개 | 범위 내 |
| 결과물 | 1개 | 없음 |
| 전이 장면 | 1개 | 없음 |
| 예상 학습 시간 | 20~25분 | 범위 내 |
| `보통` 학생 문안·활동 분량 | `m1-l1`, `m1-l4` 개정본 중앙값 | ±10% |

분량은 글자 수만으로 채우지 않는다. 이야기 이해, 증거 조작, 판단, 표현, 결과물 제작, 전이 수행에 필요한 실제 활동량으로 맞춘다. 반복 설명, 같은 의미의 선택지, 의미 없는 축하 화면은 분량으로 계산하지 않는다.

## 6. 공통 5막 스토리와 8단계 경험 구조

1. **만남**: 캐릭터가 실제 생활 목적을 가진다.
2. **어긋남**: 정보가 부족하거나 AI 답과 현실이 다르다.
3. **살펴봄**: 학생이 자료·조건·사람의 말을 비교한다.
4. **선택과 수정**: 학생이 AI 답 또는 자기 계획을 수용·수정·거절한다.
5. **남김과 전이**: 결과물을 남기고 다른 장면에 같은 전략을 써 본다.

5막은 이야기의 의미 구조이고, 8단계는 학생이 실제로 통과하는 화면 구조다. 5막을 핑계로 8단계를 줄이지 않는다.

| 이야기 막 | 대응하는 경험 단계 |
|---|---|
| 만남·어긋남 | 1. 상황 만나기, 2. 내 첫 생각 |
| 살펴봄 | 3. 새 조건 살펴보기, 4. AI와 비교하기 |
| 선택과 수정 | 5. 다시 판단하기 |
| 남김 | 6. 생각을 결과물로 |
| 전이·회고 | 7. 다른 상황에 적용하기, 8. 오늘의 기록 |

차시마다 하나의 `canonicalScenario`를 두고 다음을 모두 연결한다.

- 주인공
- 장소
- 생활 목적
- 문제 또는 어긋남
- 핵심 증거
- 조건 변화
- 학생 행동
- 결말
- 이미지 컷 번호
- 활동 자료
- 정리 반응

## 8. 이미지와 이펙트 공통 규격

### 8.1 이미지 종류

- `story`: 인물·장소·사건의 변화가 보이는 서사 컷
- `evidence`: 가격표, 영수증, 지도, 시간표, 채팅, 사진 단서처럼 판단에 쓰는 자료
- `concept`: 입력→과정→출력, 전후 비교, 순서 등 핵심 개념도
- `artifact`: 학생 결과물의 완성 예시 또는 빈 템플릿

### 8.2 생성 규칙

- 이미지 안에 글자, 말풍선 문장, UI 버튼을 넣지 않는다.
- 말풍선이 필요하면 비워 두고 HTML 텍스트로 표시한다.
- 동일 차시의 캐릭터 의상·장소·소품·시간대를 유지한다.
- 증거 자료는 학생이 실제로 비교할 수 있게 선명해야 한다.
- 장식용 이미지 한 장으로 활동을 대신하지 않는다.
- 기존 에셋은 대본과 일치할 때만 재사용한다.
- 파일명: `{lessonId}-story-01.webp`, `{lessonId}-evidence-01.webp`, `{lessonId}-concept-01.webp`

### 8.3 에셋 수량과 빈자리 계약

- 경험 차시 62개 × 이야기 4컷 = 이야기 이미지 자리 248개
- 모듈 마무리 6개 × 이야기 3컷 = 이야기 이미지 자리 18개
- 전체 이야기 이미지 계획 = 266개
- `evidence`, `concept`, `artifact`는 위 266개에 포함하지 않고 차시별 기능 자료 명세로 별도 관리한다.
- 정확한 비교와 확대가 필요한 표·지도·시간표·카드는 가능하면 접근 가능한 HTML/SVG로 구현한다.
- 이미지 생성 전 구현에서는 `imageSrc: ''`와 구체적인 `alt`, `purpose`, 생성 프롬프트를 둔다.
- 아직 없는 파일 경로를 임시로 참조하거나 기존의 관련 없는 이미지를 대신 표시하지 않는다.
- 이전 178개 에셋 산정은 폐기한다.

### 8.4 이펙트 규칙

- 이펙트는 정보 변화나 학생 행동의 결과를 보여줄 때만 사용한다.
- 권장: 가림 해제, 전후 겹치기, 근거 하이라이트, 순서 연결선, 수정 전후 diff, 진행 도장, 결과물 조립.
- 금지: 읽기를 방해하는 반복 점멸, 의미 없는 폭죽 남발, 정답을 미리 암시하는 색.
- 모든 모션은 `prefers-reduced-motion`에서 즉시 상태 변화로 대체한다.

# 10. 모듈 2 PRD: 하나의 요청을 계속 고치는 프롬프트 노트

## 10.1 모듈 목표

목적·대상·조건·형식을 넣어 요청을 만들고, AI 결과를 기준과 독립 자료로 확인하며 필요한 부분을 다시 요청한다.

## 10.2 모듈 스토리

AI 동아리는 학교 체험회 안내를 준비한다. 처음에는 `그거 만들어 줘`처럼 모호한 부탁 때문에 엉뚱한 결과가 나온다. 각 차시에서 하나의 요청 기술을 익혀 같은 안내 요청을 계속 개선한다. 마지막에는 최초 요청부터 검증과 최종 사용 판단까지 담긴 `나의 프롬프트 노트`를 완성한다.

## 10.4 모듈 2 금지 사항

- `짧을수록 좋은 프롬프트`로 단순화하지 않는다.
- 역할을 지정하면 전문 지식이나 사실성이 높아진다고 가르치지 않는다.
- 같은 AI에게 다시 묻는 것을 사실 확인 완료로 처리하지 않는다.
- `진짜 AI`라는 제목을 준비된 응답에 사용하지 않는다.
- `m2-l6`과 `m2-l10`에서 같은 학교 준비물 사건을 반복하지 않는다.

# 11. 모듈 3 PRD: 나의 공부 도우미 도구함

## 11.1 모듈 목표

공부 목적에 맞게 AI에게 질문하고, AI 결과를 원문·사전·계산기·그림과 비교하며 내 말과 생각으로 학습 결과를 완성한다.

## 11.2 모듈 스토리

AI 동아리는 학교 배움 전시회에서 `AI와 공부하는 방법`을 소개하기로 한다. 진우와 윤아는 모르는 말, 어려운 설명, 계산, 긴 글, 퀴즈, 그림 설명에 AI를 시험한다. AI 결과를 그대로 제출하지 않고 다른 자료와 비교하고 자기 말로 고친다. 마지막에는 `나의 공부 도우미 도구함`을 완성한다.

## 11.4 모듈 3 금지 사항

- AI 정의만 묻는 것으로 복습을 대신하지 않는다.
- 계산을 AI에게 먼저 맡기고 계산기를 보조 검산으로 두지 않는다.
- 퀴즈 정답을 학생 응답 전에 공개하지 않는다.
- 쉬운 설명을 위해 틀린 비유를 사용하지 않는다.
- 한 차시에 서로 다른 이야기 세계와 대상 이미지를 혼합하지 않는다.

# 12. 모듈 4 PRD: AI 안전 여권

## 12.1 모듈 목표

AI·온라인 정보의 오류와 위험 신호를 확인하고, 개인정보를 보호하며, 멈춤·거절·도움 요청 행동을 실제 문장으로 수행한다.

## 12.2 모듈 스토리

학교 AI 체험회 공개 전, 동아리는 안전 점검을 한다. 잘못된 시간표, 개인정보가 보이는 사진, 비밀번호 요구, 불편한 메시지, 광고처럼 보이지 않는 추천을 발견한다. 학생은 `확인하기`, `가리기`, `거절하기`, `믿을 만한 사람에게 알리기` 도장을 모아 마지막에 `AI 안전 여권`을 만든다.

## 12.3 안전 정본 규칙

1. 비밀번호와 인증 코드는 채팅 상대에게 누구에게도 보내지 않는다.
2. 계정 복구는 보호자·교사와 공식 절차에서 함께 할 수 있지만 비밀번호를 메시지로 전달하는 것과 구분한다.
3. 사진은 대상만 보고 안전/위험을 절대 분류하지 않는다. 얼굴, 이름표, 위치, 일정, 다른 사람, 공유 상대와 목적을 함께 본다.
4. 유해 콘텐츠는 학생에게 직접 모욕 문장을 읽게 하지 않는다. 가려진 자료로 위험 신호를 연습한다.
5. 증거 보존 행동은 상황·학교 규정·성인 안내에 따라 다를 수 있다. 학생이 혼자 다시 위험 자료를 열게 하지 않는다.
6. 사용 시간은 보편적 한 숫자로 가르치지 않는다. 학생·가정·학교가 함께 정한 계획을 사용한다.

## 12.5 모듈 4 금지 사항

- 환각을 의도적인 거짓말로 정의하지 않는다.
- 비밀번호·인증 코드를 교사나 보호자에게 메시지로 보내도 된다는 예외를 만들지 않는다.
- 꽃·구름·음식 사진을 맥락 없이 `무조건 안전`으로 분류하지 않는다.
- 불편한 문장을 학생에게 직접 모욕 형태로 읽게 하지 않는다.
- 사용 시간 한 숫자를 사실 카드로 제시하지 않는다.
- AI에게 다시 묻는 것으로 검증을 완료하지 않는다.

# 13. 모듈 5 PRD: 문제 해결 지도

## 13.1 모듈 목표

현재 상태와 목표의 차이를 찾고, 문제를 작은 과제로 나누며, 순서·우선순위·도움 수준을 정하고, 결과를 확인해 계획을 수정한다.

## 13.2 모듈 스토리

학교 AI 체험회 준비 중 여러 문제가 생긴다. 필요한 물건이 늦게 오고, 설치 순서가 꼬이며, 아이미가 장소를 다르게 알아듣고, 준비 도구가 부족해 계획을 바꿔야 한다. 진우와 윤아는 문제를 비난이나 실패로 보지 않고 `현재-목표-정보-방법-확인` 지도로 풀어 간다. 마지막에는 새 문제를 스스로 해결해 `문제 해결 지도`를 완성한다.

## 13.4 모듈 5 금지 사항

- 학생의 표현이 애매해 AI가 틀렸다고 책임을 학생에게 돌리지 않는다.
- 분해와 순서를 같은 활동으로 처리하지 않는다.
- 숙제·놀이처럼 도덕적 단일 정답만 제시하지 않는다.
- 컴퓨터 부수기, 공책 찢기 같은 과장 오답을 사용하지 않는다.
- 실제 조리 수행을 요구하거나 안전 조건 없이 조리 성공을 축하하지 않는다.

# 14. 모듈 6 PRD: 나의 AI 생활 포트폴리오

## 14.1 모듈 목표

생활 목적과 조건을 확인하고, AI 초안이나 디지털 정보를 실제 자료·도구·사람과 비교하여 내가 선택하고 행동한 뒤 결과를 돌아본다.

## 14.2 모듈 스토리

AI 동아리는 학교 밖 마을 생활 미션에 나선다. 장보기, 돈 계산, 길과 교통, 날씨, 음식 계획, 일정, 건강, 소통, 직업 탐색, 자기소개를 경험한다. AI는 초안과 연습을 돕지만 실시간·건강·안전 정보는 공식 자료와 사람을 우선한다. 마지막에는 하루 생활 프로젝트와 졸업 발표로 `나의 AI 생활 포트폴리오`를 완성한다.

## 14.3 공통 생활 판단 루프

`내 목적과 조건 → AI/디지털 정보 → 실제 자료와 사람 확인 → 내가 선택 → 행동·표현 → 결과 돌아보기`

## 14.5 모듈 6 금지 사항

- 실제 위치 자료 없이 AI가 길을 생성하게 하지 않는다.
- 지역·날짜가 없는 AI 답을 실시간 날씨로 사용하지 않는다.
- 존재하지 않는 병원과 거리를 사실처럼 제시하지 않는다.
- 건강 증상만으로 병원을 선택하거나 진단하게 하지 않는다.
- 생활 예절을 순응과 칭찬 중심으로만 가르치지 않는다.
- 직업 소멸이나 AI 자동화 영향을 단정적으로 가르치지 않는다.

# 16. 콘텐츠 데이터 정본 요구사항

## 16.1 차시별 단일 정본

각 차시는 다음 판별 가능한 단일 콘텐츠 정의를 사용해야 한다. 실제 타입 이름은 구현 계획에서 저장소 패턴에 맞게 정하되 의미를 분산하지 않는다.

interface ExperienceLessonDesign extends CanonicalLessonBase {
  lessonType: 'experience';
  visualNovel: {
    scenes: readonly [StoryScene, StoryScene, StoryScene, StoryScene];
  };
  stages: readonly [
    ExperienceStage<'encounter'>,
    ExperienceStage<'first-attempt'>,
    ExperienceStage<'condition-change'>,

## 16.3 기존 데이터 처리

- 보존: 성취기준 코드, 학생 사전 중 정확한 정의, 실제로 동작하는 접근성 기능
- 재검토 후 보존: 새 정본 사건과 정확히 일치하는 기존 이미지와 기능 자료

# 17. 활동 설계 품질 기준

## 17.1 좋은 활동

- 학생이 실제 자료를 보고 판단한다.
- 복수의 그럴듯한 선택지 사이에서 이유를 표현한다.
- 첫 시도와 수정 결과가 남는다.
- AI 답과 학생 선택을 구분한다.
- 결과물이 다음 차시와 모듈 마무리에서 다시 쓰인다.

## 17.2 금지 활동

- 설명을 그대로 다시 묻는 OX
- 정답이 윤리적으로 너무 뻔한 선택
- `좋은 행동/나쁜 행동` 이분법만 반복
- 결과를 보지 않고 좋은 프롬프트를 고르는 활동
- 학생 응답 전에 정답을 보여 주는 퀴즈
- 기능적 자료 없이 상상으로 돈·길·날씨·건강 정보를 판단하는 활동
- 마지막에 의미 없는 다짐·폭죽·배지만 추가하는 활동

## 17.3 오답 설계

오답은 실제 학생이 선택할 수 있는 그럴듯한 이유를 가져야 한다.

- 정보가 한 가지 빠진 답
- 최신성은 있지만 공식성이 낮은 자료
- 형식은 맞지만 중요한 사실이 빠진 결과
- 안전하지만 목적을 충분히 달성하지 못한 방법
- 빠르지만 확인 절차가 없는 선택

학생을 조롱하거나 파괴·폭력·무모함을 과장한 오답은 금지한다.

# 18. 수행 증거와 포트폴리오

## 18.1 모든 차시의 최소 증거

- 첫 시도 또는 첫 판단
- 사용한 지원 방식
- 최종 표현 또는 결과물
- 바뀐 점 또는 선택 이유
- 전이 과제 결과

## 18.2 모듈 마무리

모듈 마무리는 일부 대표 차시만 불러오지 않는다. 해당 모듈의 모든 경험 차시 산출물을 목록으로 보여 주고 학생이 최소 3개를 선택하게 한다.

증거가 없는 경우에도 빈값을 성공처럼 꾸미지 않는다. 학생은 새 통합 과제를 수행해 실제 결과물을 남겨야 완료할 수 있다.

## 18.3 개인정보

- 자유 텍스트·음성·그림은 로컬 저장을 기본으로 한다.
- 학생 실명 대신 별칭을 사용한다.
- 이미지·음성 원본 저장은 교사 설정과 명시적 동의가 있을 때만 허용한다.
- AI 전송 전 개인정보 경고와 로컬 준비된 응답 경로를 제공한다.

# 19. Antigravity 실행 지침

## 19.1 작업 원칙

1. 68차시를 한 번에 대량 치환하지 않는다.
2. 모듈 하나를 완성하고 사용자 승인 후 다음 모듈로 간다.
3. 각 모듈에서 먼저 콘텐츠 정본과 에셋 명세를 작성하고, 그다음 화면에 연결한다.
4. 기존 문장을 자동 존댓말 변환하거나 어려운 동의어로 확장하지 않는다.
5. 새 문안은 한국어 문법 검토와 TTS 낭독 검토를 거친다.
6. 차시별 구현 전에 이 PRD 행을 체크리스트로 복사하고 누락 없이 대응한다.

## 19.2 권장 작업 순서

### 단계 0: 기반 정리

- 차시별 실제 라우팅과 도달 불가능 콘텐츠 목록 확정
- `CanonicalLessonDesign` 데이터 구조 확정
- 경험 차시 62개가 사용할 단일 8단계 스튜디오 렌더 구조 확정
- 모듈 마무리 6개가 사용할 통합 수행 렌더 구조 확정
- 기존 증거 저장과 포트폴리오 호환 전략 확정
- 4컷 빈 이미지 자리와 실제 파일 참조를 구분하는 검사 자동화
- 경험 차시 62개 × 8단계, 62개 × 4장면 구조 검사 추가
- `flagship`, `guided`, 일반 `steps` 우회 경로 제거 계획 확정
- 한국어 비문·금지 전문어 검사 추가

### 단계 1: 모듈 1 파일럿

- `m1-l1`, `m1-l4`의 정보 밀도와 판단 변화 품질을 공통 기준선으로 측정
- `m1-l2`를 가장 짧은 기존 차시의 승격 시험 사례로 삼아 8단계 전체 구현
- `m1-l1~l10` 모두 같은 렌더러, 8단계, 4컷 빈자리, 20~25분 예산으로 구현
- `m1-l11` 모듈 마무리 구현
- `m1-l2`, `m1-l3`, `m1-l5~l9`가 일반 `MicroLessonFrame`이나 축약 경로로 빠지지 않는지 확인
- 1280px, 390px, 125% 글자 크기 검증
- 사용자 승인 게이트

### 단계 2~6: 모듈별 확장

각 모듈에서 다음 순서를 반복한다.

1. 모듈 전체 경험 차시의 정본 사건과 8단계 대본 확정
2. 모듈 전체 경험 차시를 같은 렌더러에 연결
3. 차시마다 4컷 빈자리와 기능 자료 최소 2종 연결
4. 모듈 마무리 1개와 전체 산출물 회수 연결
5. 단계 수·분량·이미지 자리·포트폴리오 자동 검사
6. 콘텐츠 정확성·문법·접근성·디자인 동급성 검증
7. 사용자 승인

이미지는 별도 생성 단계에서 제작한다. 이미지 생성 전에는 구체적인 장면 설명을 가진 빈자리를 사용하며, 이미지가 없다는 이유로 기존의 관련 없는 이미지를 재사용하거나 화면 구조를 축소하지 않는다.

### 단계 7: 교과서 전체 연결

- 모듈 간 누적 산출물 확인
- M6 졸업 프로젝트에서 6개 모듈 기록 회수
- 중복 소재·용어·안전 규칙 최종 감사
- 전체 68차시 시작부터 완료까지 스모크 검증

# 20. 검증 게이트

## 20.1 콘텐츠 정합성

- [ ] 각 차시에 고정 학습목표가 정확히 1개 있다.
- [ ] 목표의 행동을 실제 활동에서 수행한다.
- [ ] 핵심 개념이 활동과 정리에서 같은 의미로 유지된다.
- [ ] 같은 차시의 이야기·이미지·활동·결말이 한 사건이다.
- [ ] 모듈 이야기에서 이전 차시 산출물이 다음 차시에 등장한다.
- [ ] 모듈 마무리가 전체 경험 차시 산출물을 선택할 수 있다.
- [ ] 62개 경험 차시가 모두 8단계 판단 변화 서사를 가진다.
- [ ] 기존에 짧았던 44개 차시가 설명이나 퀴즈를 나눈 것이 아니라 조건 변화와 전이를 새로 갖는다.

## 20.2 정확성·안전

- [ ] AI·자동화·로봇·검색 연결 AI를 절대 명제로 잘못 구분하지 않는다.
- [ ] 같은 AI에게 다시 묻는 것을 독립 검증으로 처리하지 않는다.
- [ ] 길·교통·날씨는 공식 최신 자료를 우선한다.
- [ ] 돈 계산은 계산기를 기본 도구로 사용한다.
- [ ] 건강은 사람과 전문 기관 우선이며 AI 진단을 사용하지 않는다.
- [ ] 비밀번호·인증 코드·사진·개인정보 규칙이 전 차시에서 일치한다.
- [ ] 유해 콘텐츠를 불필요하게 재현하지 않는다.

## 20.3 언어

- [ ] `습니다` 활용 오류가 없다.
- [ ] 의미 없는 영어 혼용이 없다.
- [ ] TTS로 읽었을 때 자연스럽다.
- [ ] 한 문장에 핵심 정보가 하나다.
- [ ] 학생 대상 미정의 전문 용어가 없다.
- [ ] 캐릭터 말투가 장면과 관계에 맞다.

## 20.4 활동

- [ ] 62개 경험 차시마다 서로 다른 고유 증거 활동이 있다.
- [ ] 모든 경험 차시에 첫 판단, 새 조건, AI 비교, 재판단, 결과물, 전이가 있다.
- [ ] 8단계 중 빈 단계·읽기만 하는 단계·병합된 단계가 없다.
- [ ] 의미 있는 상호작용이 차시당 6~8개다.
- [ ] 예상 학습 시간이 20~25분이며 `보통` 분량 편차가 기준 중앙값의 ±10% 안이다.
- [ ] 오답이 그럴듯하며 학생을 희화화하지 않는다.
- [ ] 첫 판단과 최종 판단을 비교할 수 있다.
- [ ] 결과물이 저장·인쇄·포트폴리오 선택 중 하나를 지원한다.
- [ ] 지원을 받아 진행할 수 있되, 모듈 마무리 완료는 실제 산출물을 요구한다.

## 20.5 이미지·UI

- [ ] 62개 경험 차시마다 정확히 4개의 이야기 이미지 자리가 있다.
- [ ] 이미지 생성 전 빈자리는 `imageSrc: ''`, 구체적인 `alt`, `purpose`, 생성 프롬프트를 가진다.
- [ ] 비어 있지 않은 모든 이미지 참조는 실제 파일이 존재한다.
- [ ] 이미지의 인물·소품·장소가 대본과 일치한다.
- [ ] 판단에 필요한 증거가 글자 크기 확대 상태에서도 보인다.
- [ ] 이미지에 생성된 글자나 완성 말풍선이 없다.
- [ ] 62개 경험 차시가 같은 스튜디오 렌더러·진행 표시·스프레드 위계를 사용한다.
- [ ] 차시별로 카드 크기, 여백, 배경 밀도, 이미지 비율을 낮춘 축약 디자인이 없다.
- [ ] 1280px에서 디지털 만화책 스프레드 위계가 유지된다.
- [ ] 390px와 125% 글자 크기에서 잘림·가로 스크롤이 없다.
- [ ] 모든 이펙트가 reduced-motion 대체 상태를 갖는다.

## 20.6 기술 검증

- [ ] `npm run lint`

- [ ] 이미지 참조 존재 검사
- [ ] 68개 차시 정본 데이터 커버리지 검사
- [ ] 경험 차시 62, 모듈 마무리 6 유형 수 검사
- [ ] 경험 차시의 8단계 × 62개 구조 검사
- [ ] 경험 차시의 4장면 × 62개 구조 검사

# 21. 완료 정의

이 프로젝트는 다음 조건을 모두 만족할 때 완료다.

1. 68개 차시가 이 PRD의 목표·개념·스토리·활동·에셋 요구와 일치한다.
2. 기존의 중복 정본과 도달 불가능 콘텐츠가 제거되거나 명시적 호환 레이어로만 남는다.
3. 도전적 수준이 전문어가 아니라 증거·예외·전이의 깊이로 구현된다.
4. 모든 차시에 실제 수행 증거가 남고 모듈 마무리에서 회수된다.
5. 모듈 1부터 모듈 6까지 하나의 AI 동아리 성장 서사가 이어진다.
6. 학생에게 AI 능력을 과장하거나 안전하지 않은 행동을 가르치는 문장이 없다.
7. 사용자 승인 게이트를 모듈별로 통과한다.
8. 경험 차시 62개가 모두 동일한 8단계 스튜디오와 20~25분 제작 예산을 충족한다.
9. 기존 44개 축약 차시와 기존 18개 대표 차시 사이에 화면 수·이미지 수·디자인 밀도·활동 품질 차이가 없다.
10. 이미지 생성 전에도 266개 이야기 이미지 자리가 깨진 참조 없이 의도된 비율과 설명을 유지한다.

# 22. Antigravity에게 전달할 작업 명령

다음 문장을 이 PRD와 함께 전달한다.

> `docs/superpowers/specs/2026-07-23-68-lesson-content-remodel-prd.md`를 제품 정본으로 사용하라. `플래그십 18개/안내 연습 44개` 구분을 완전히 폐기하고 모듈 마무리 6개를 제외한 62개 차시를 모두 같은 핵심 경험으로 구현하라. 62개 차시는 예외 없이 같은 스튜디오 렌더러, 정확히 8단계, 서로 이어지는 이야기 4컷, 기능 자료 최소 2종, 의미 있는 상호작용 6~8개, 첫 판단, 조건 변화, AI 비교, 재판단, 고유 결과물, 새 상황 전이, 20~25분 분량을 가져야 한다. 기존의 짧은 차시를 8조각으로 나누거나 문장만 늘리지 말고 각 차시의 판단 변화 서사를 새로 설계하라. 이미지는 지금 생성하지 말고 `imageSrc: ''`와 구체적인 장면 설명을 가진 빈자리로 두며, 없는 파일 경로를 만들지 마라. 기존 68차시 문안을 부분 보정하거나 도전적 화면만 덧붙이지 말고 차시별 단일 정본 사건과 고정 학습목표를 먼저 확정한 뒤 이야기·지식·활동·이미지·수행 증거를 함께 리모델링하라. 모듈 1부터 순서대로 작업하고 각 모듈 완료 후 1280px, 390px, 125% 글자 크기 브라우저 검증과 사용자 승인 전에는 다음 모듈로 넘어가지 마라. 기존 콘텐츠와 PRD가 충돌하면 PRD를 우선하되, 성취기준 코드는 검증 없이 새로 만들지 마라.

# 23. 안전·교육 설계 근거

이 PRD의 안전 기준은 다음 공식 자료의 원칙과 맞춘다.

- [UNESCO 생성형 AI 교육·연구 가이드](https://www.unesco.org/en/articles/guidance-generative-ai-education-and-research): 인간의 주체성, 연령과 능력에 맞는 설계, 개인정보 보호, 교육적·윤리적 검증, AI 결과에 대한 비판적 확인을 기준으로 삼는다.
- [WHO 건강 분야 생성형 AI 안전 권고](https://www.who.int/news/item/16-05-2023-who-calls-for-safe-and-ethical-ai-for-health): 건강 관련 LLM 사용에는 주의, 안전, 인간의 자율성, 책임과 적절한 거버넌스가 필요하다는 원칙을 적용한다.
- [CISA 학교·온라인 안전 자료](https://www.cisa.gov/sites/default/files/2023-07/Cyber%20Education%20and%20School%20Safety%20Resources_V2_508c.pdf): 개인정보 보호, 낯선 링크와 요청에 대한 주의, 온라인 위험의 도움 요청 원칙을 반영한다.
- [FTC 아동 온라인 개인정보 안내](https://consumer.ftc.gov/consumer-alerts/2019/04/coppa-few-tips-keep-your-child-safe-online): 이름·주소·전화번호·계정 정보 등 아동 개인정보를 제한하고 보호자와 함께 온라인 활동을 점검하는 원칙을 반영한다.

외부 자료의 문장을 학생 콘텐츠에 그대로 복사하지 않는다. 구현 시 대한민국 학교와 지역 지침에 맞는 표현을 교사가 다시 검토한다.
